# 2.1.0：随机神秘砖与连续奇遇验收

日期：2026-10-26（Asia/Shanghai）。小米 15 `dada`，Android 17。

## 修改原因

2.0 固定选择最下排中央的砖，导致神秘砖太容易在开局被命中；奖励关还要选升级、领奖，并在返回后点继续，割裂了动作节奏。

2.1 从砖阵内部等概率随机抽取神秘砖，避开最先接触的底排；短奇遇自动装配升级，结束后自动发奖返回，恢复原来运行中的碰界局面。未发球状态触发传送时，回来也会自动发球。主动暂停、失焦和后台保护保留。

## 纯 Java 回归

`test.ps1` 两套测试全部通过。布局输出：

```text
Placement: 360 layouts, 13 rows / 67 horizontal positions, no front-row portal
```

覆盖随机位置、相同种子可重现、排除首排、传送冻结、快照、奖励幂等、取消后自动继续、返回后球运动、未发球状态自动发球、最后砖清关、非法快照、升级持续转向、三波节奏和战斗终局。

## 节奏探针

`BalanceProbe challenge` 用 16 个固定种子、持续绕行和主动释放脉冲模拟 30 秒奇遇：首次升级为 4.8–7.1 秒，击破 70–79 个敌人，峰值同时存在 11–20 个敌人，16 局均完成。此数据反映指定模拟驾驶，不等同于所有玩家难度或对游戏趣味的保证。

短奇遇三波分别是侦察群、侧翼夹击、弹幕突围。射击由初始 3.6 次/秒提高至 6 次/秒，奇遇开局双弹；更早吸附星尘，加入连破提示和冲刺预警。普通航程仍保留手动选择升级。

## 真机连续流程

`CollectionSmokeInstrumentation` 以真实绘制时钟运行，不点击领奖、返回或继续，也不代选升级。模拟驾驶只移动目标并释放充好的脉冲。实际输出：

```text
Star challenge running: 0/30 s, wave=1, level=1, kills=0, hp=100
Star challenge running: 5/30 s, wave=1, level=1, kills=4, hp=100
Star challenge running: 10/30 s, wave=2, level=2, kills=11, hp=100
Star challenge running: 15/30 s, wave=2, level=4, kills=20, hp=120
Star challenge running: 20/30 s, wave=3, level=6, kills=28, hp=140
Star challenge running: 25/30 s, wave=3, level=8, kills=48, hp=180
Success and duplicate-result checks passed; verifying cancellation
Cancellation continues automatically; verifying defeated encounter also returns
PASS: collection portal smoke test; preferences_restored=true
```

检查结果：

- 命中神秘砖后，由正常绘制流程自动打开星隙。
- 30 秒内不出现升级选择窗，升级不会释放拖动目标。
- 结束后经过约 0.65 秒自动过场，不出现领奖按钮。
- 奖励与结算计算值相同，奖励持久化后的原局快照保留原来的球位置、速度、砖块血量、关卡和生命。
- 返回时引擎为 `PLAYING`，继续计时并运动，无需点继续；重复结果不能再次加分。
- 主动取消返回继续运行；注入正常伤害导致挑战失败后也自动返回。
- 三份游戏偏好在测试结束后逐键恢复。最终 Release 覆盖安装后，保留用户第 23 关及最高分 189950。测试辅助包已移除。

最后补充的“未发球状态自动发球”分支经纯 Java 测试验证；此前已覆盖的正常运行中完整往返无需重复执行。未做整机进程故障注入；相关快照与补领边界见初版报告。
