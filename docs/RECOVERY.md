# 碰界源码恢复说明

记录日期：2026-10-26。

## 来源

用户提供 `https://github.com/Jeremy-Jia/Games.git` 作为统一仓库时，仓库为空，原「碰界」没有已上传、可拉取的源代码。恢复工作以用户自己手机上已安装的 APK 为依据：

- 应用包名：`dev.brickzen.app`
- 原版本：`1.3.0`
- 原版本号：`6`
- 新游戏集版本：`2.0.0`，版本号 `7`

原 APK、提取过程产物和用户个人存档备份保存在本机仓库之外的 `work/brickzen-integration/` 工作目录中。它们不作为源码提交，也不随本仓库分发。

## 恢复了什么

从 APK 中提取游戏资源，对 DEX 代码进行反编译，并修复反编译后无法直接编译的表达式、类型和 Android 宿主代码，形成可维护的 Gradle Android 工程。

恢复工程保留了原碰界的游戏引擎、绘制与交互逻辑，以及图标、声音和主题资源。无限/挑战模式、砖块形状、道具、连击、原有设置与存档键沿用原实现。新代码另加入集锦入口、神秘砖块与星隙奖励关，不把恢复工作描述为重新设计原有玩法。

反编译生成的临时变量名和 `JADX` 注释可能仍可见，它们反映恢复来源。后续重构应通过引擎回归和设备对照确认行为，避免仅因名字不直观就大规模替换。

## 无法恢复的内容

APK 不包含原仓库的提交历史、分支、完整源码注释或原构建环境，因此本工程不声称恢复了这些信息。反编译结果也不保证与原作者源文件逐字一致。

APK 只携带签名证书及签名结果，不包含用于签名的私钥。恢复源码不会恢复原签名密钥；密钥须由其持有者另行提供。仓库不提交任何 `.keystore`、`.jks`、密码或设备认证信息。

本轮尚未完成的真机验收应继续明确标记为待验收，不能以“恢复成功”替代所有玩法的兼容性结论。

## 存档兼容边界

应用 ID 保持 `dev.brickzen.app`，碰界继续读取私有 SharedPreferences `brickzen`，包括：

| 类别 | 原有键 |
| --- | --- |
| 关卡和纪录 | `zen_level`、`best_zen`、`best_challenge` |
| 操作和反馈 | `paddle_lift`、`sound`、`haptic` |
| 外观 | `appearance` |

同签名覆盖安装不会因这次入口调整而更换这些存档位置。若需要更换签名，Android 的安装限制与卸载清数据行为仍然存在；必须明确处理备份恢复，不能假定换签名后旧私有目录自动保留。

新增星隙使用独立的 `star_drift` 偏好文件；跨游戏局面快照保存在碰界私有存储中，待领取奇遇奖励保存在 `portal_results`。这些都是用户数据，不能拿真实设备上的内容做仓库样例。

## 后续维护

- 保留原有包名、存档键和用户设置语义，修改格式时提供迁移。
- 快照有单独格式版本；修改可序列化对象时，同时检查旧快照兼容与失败回退。
- 源码可重新构建，发布签名由维护者独立管理。
- 将实际执行的测试、设备版本、安装方式和已知限制写入验收记录；源码与 APK 的可编译性不等同于所有设备表现已验证。
