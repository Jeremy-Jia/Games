# 游戏集架构

## 应用与模块

这是一个 Android 应用、一个 `:app` Gradle 模块，不是安装两个 APK 的启动器。应用 ID 为 `dev.brickzen.app`，两款游戏在不同 Java 包内运行，分享应用私有目录，但各自维护游戏逻辑与偏好。

| 组件 | 职责 |
| --- | --- |
| `dev.brickzen.app.CollectionActivity` | 唯一 Launcher 入口；展示碰界、星隙和本地纪录，沿用碰界外观选择。 |
| `dev.brickzen.app.MainActivity` | 原碰界的 Android 宿主、设置窗口、刷新率与奇遇交接。 |
| `dev.brickzen.app.GameEngine` | 纯 Java 砖块物理、关卡、道具、暂停状态及可持久化局面快照。 |
| `dev.brickzen.app.GameView` | Canvas 绘制、触摸、原有纪录与设置、神秘砖块提示。 |
| `io.github.jeremyjia.stardrift.MainActivity` | 星隙的 Android 生命周期、音效、震动、纪录以及奇遇结果。 |
| `io.github.jeremyjia.stardrift.GameEngine` | 纯 Java 战斗模拟；按击破目标推进波次，最终 Boss 决定通关。 |
| `io.github.jeremyjia.stardrift.GameView` | 星空绘制、拖动控制、暂停、三选一升级与结算。 |

只有集锦首页 Activity 对外导出。两款游戏 Activity 都是应用内部入口。Manifest 仅申请震动权限，没有网络与 Root 权限。

## 两种星隙模式

标准航程从集锦星隙卡片进入，消灭六波敌人后出现最终 Boss；击败 Boss 后胜利，没有时间限制。得分、击破数、航行次数与最佳纪录写入 `star_drift`。

奇遇从碰界内部传入 `bonus_mode=true` 和 `portal_id`。引擎使用四波敌阵与最终 Boss，同样没有倒计时；奇遇计数与标准航程纪录分开，返回时将奖励交给碰界。

两种模式都保留拖动移动、自动射击、星尘升级和主动脉冲。普通航程升级暂停并让玩家三选一；奇遇升级立即随机装配，不释放拖动目标，不暂停计时。离开前台或失去窗口焦点仍暂停，重新进入时由玩家继续。

## 神秘砖块交接

1. 每关从内部砖块中等概率抽取一块神秘砖，排除小球最先接触的底排。第一次命中先完成伤害与反弹，再冻结后续模拟，生成唯一 `portal_id`。
2. 碰界宿主将完整引擎快照写入 `brickzen.portal_snapshot`；确认写入成功后，才启动星隙奇遇 Activity。
3. 星隙按击破目标推进四波敌阵，最后生成一个 Boss，升级自动装配。击败 Boss 或玩家阵亡后显示约 0.65 秒过场，自动把结果同步写入私有 `portal_results`，并通过 Activity 结果传回相同 `portal_id`，不需要点击领奖。
4. 碰界验证当前确有待完成奇遇且 ID 一致，将额外分数限制在 `0–3000`。击败 Boss 额外赋予 14 秒宽板与满格脉冲能量；取消不发奖励。
5. 碰界先持久化已结算的局面，再删除待领取结果，恢复传送前的运动状态。计时器从当前帧重置，奇遇耗时不会被当作原局的物理时间；返回即继续，不显示暂停确认。

引擎的 `portalActive` 门控防止同一结果重复加分；宿主同时核对 ID，避免旧结果作用于新局。同步写入失败时保留可重试的状态，不直接宣告奖励已经领取。

快照保留砖块、反弹障碍、球的位置和速度、生命、分数、关卡、道具剩余时间、连锁效果和随机数状态，因此奇遇期间不会继续丢球或消耗原局计时。障碍独立于可破坏砖块，不参与清关计数、奖励与神秘砖抽取；旧版快照没有障碍时按空集合读取。快照还要覆盖“神秘砖恰好是最后一块砖”等边界。

## 进程重建与数据边界

碰界 Activity 重新创建时读取保存的局面。仍有待完成奇遇时查询 `portal_results`，消费已写入而未通过正常回调送达的结果；没有结果时，在窗口真正获得前台焦点后自动重进奇遇，避免恢复页再次要求点击进入。普通的后台重开仍保留暂停保护。这不表示星隙所有运行中帧都具有跨进程实时存档。

快照使用 `BRICKZEN_PORTAL_V1:` 前缀、Base64 和 Java 对象序列化，仅用于应用可信私有存储。读取限制解码大小为 1 MiB，限制允许反序列化的类，并检查实体数量、数值有效性和关卡状态。它不是公共导入格式，不应增加从网页、剪贴板或任意下载文件直接导入对象快照的入口。

| 偏好文件 | 数据 |
| --- | --- |
| `brickzen` | 原碰界关卡、纪录、设置；新增奇遇局面快照和返回提示。 |
| `star_drift` | 星隙声音、触感、减少动态、标准航程纪录及奇遇次数。 |
| `portal_results` | 按 `portal_id` 索引的待领取奇遇结果，消费成功后删除。 |

## 开发与验证

两套引擎都不依赖 Android，可以用 JDK 17 直接跑 `tests/BrickEngineTest.java` 与 `tests/GameEngineTest.java`。构建环境和命令见仓库 README。

引擎回归重点是障碍反弹与清关、物理更新在交接点真正停止、完整快照往返、随机状态保留、取消不扣命、奖励只发一次，以及波次目标、Boss 终局和暂停。`BalanceProbe` 只做模拟驾驶与种子对照。

最新设备验收结果记录在 [2.2.0.md](verification/2.2.0.md)，此前限时版本保留在 [2.1.0.md](verification/2.1.0.md)，初版记录见 [REPORT.md](verification/REPORT.md)。维护时仍应核对以下流程，并区分已完成的真实运行与未覆盖的故障场景：

- 同签名覆盖安装后的原关卡、纪录、外观和挡板设置。
- 集锦进入、返回两款游戏；挖孔、系统栏和触控布局。
- 实际击中神秘砖，完整完成或取消奇遇，回到正确的原局。
- 锁屏、后台、窗口失焦时暂停及音效停止。
- 奇遇结果已写入而父 Activity 被重建时补领，重复回调不重复加分。
- 进程重启后的局面恢复及损坏快照的处理。

签名密钥、原 APK 和用户存档备份不参与构建源码，不进入版本控制。
